# Django Project Structure — File by File

This document explains every file in the `mysite` project and the `blog` app in this repository.

> **Project vs App**
> - A **project** (`mysite`) is the whole website: configuration, root URLs and server entry points. There is one per site.
> - An **app** (`blog`) is a self-contained feature (models, views, URLs, templates). A project can contain many apps, and apps can be reused in other projects.

```
mysite/                         ← outer folder (just a container)
├── manage.py
├── requirements.txt
├── mysite/                     ← project package
│   ├── __init__.py
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   └── wsgi.py
└── blog/                       ← app package
    ├── __init__.py
    ├── admin.py
    ├── apps.py
    ├── models.py
    ├── views.py
    ├── urls.py
    ├── tests.py
    ├── migrations/
    │   ├── __init__.py
    │   └── 0001_initial.py
    └── templates/blog/
        ├── post_list.html
        └── post_detail.html
```

---

## 1. Outer folder

### `mysite/` (outer)
A plain container for the project. Its name does not matter to Django and can be renamed freely.

### `manage.py`
Command-line utility for this project. It sets `DJANGO_SETTINGS_MODULE=mysite.settings` and forwards commands to Django.

| Command | Purpose |
|---|---|
| `python manage.py runserver` | Start the development server at http://127.0.0.1:8000/ |
| `python manage.py startapp <name>` | Create a new app |
| `python manage.py makemigrations` | Create migration files from model changes |
| `python manage.py migrate` | Apply migrations to the database |
| `python manage.py createsuperuser` | Create an admin login |
| `python manage.py test` | Run tests |

You normally never edit this file.

### `requirements.txt`
Python packages the project needs (`Django`, `djangorestframework`, `django-cors-headers`). Install with `pip install -r requirements.txt`.

### `db.sqlite3` *(generated, not in git)*
The default SQLite database, created by `migrate`. It is listed in `.gitignore` so each developer has their own local copy.

## 2. Project package — `mysite/mysite/`

### `__init__.py`
Empty file that marks the folder as a Python package, so `mysite.settings` and `mysite.urls` can be imported.

### `settings.py`
All configuration for the project. Key settings:

| Setting | Meaning |
|---|---|
| `BASE_DIR` | Path to the outer project folder; used to build other paths |
| `SECRET_KEY` | Used for signing sessions and tokens — keep secret in production |
| `DEBUG` | `True` shows detailed error pages; must be `False` in production |
| `ALLOWED_HOSTS` | Host names this site may serve (`127.0.0.1`, `localhost`) |
| `INSTALLED_APPS` | Every app Django should load — built-in apps, `rest_framework`, `corsheaders`, and our `blog` app |
| `MIDDLEWARE` | Layers every request/response passes through (security, sessions, CSRF, auth, CORS) |
| `ROOT_URLCONF` | `'mysite.urls'` — the first URL file Django reads |
| `TEMPLATES` | Template engine config; `APP_DIRS=True` finds `templates/` inside each app |
| `WSGI_APPLICATION` | Path to the WSGI app used by production servers |
| `DATABASES` | Database connection (SQLite by default) |
| `STATIC_URL` / `STATIC_ROOT` | URL prefix and collection folder for CSS/JS/images |
| `CORS_ALLOWED_ORIGINS` | Lets the React dev server (`http://localhost:5173`) call the API |

> An app is only active after it is added to `INSTALLED_APPS`. Otherwise its models, admin, templates and migrations are ignored.

### `urls.py` (project)
The **root URL configuration**. Every request starts here.

```python
urlpatterns = [
    path('admin/', admin.site.urls),
    path('blog/', include('blog.urls')),
]
```
`include()` hands everything under `/blog/` to the blog app's own `urls.py`.

### `wsgi.py`
Entry point for **WSGI** servers (Gunicorn, Apache `mod_wsgi`) used in traditional production deployments. Exposes a callable named `application`.

### `asgi.py`
Entry point for **ASGI** servers (Uvicorn, Daphne). Needed for async views and WebSockets.

## 3. App package — `mysite/blog/`

Created with `python manage.py startapp blog`.

### `__init__.py`
Marks `blog` as a Python package.

### `apps.py`
Defines `BlogConfig`, the app's configuration class (name, default primary-key type). `'blog'` in `INSTALLED_APPS` resolves to this.

### `models.py` — the **M** in MTV
Defines database tables as Python classes. Our `Post` model:

| Field | Type |
|---|---|
| `title` | `CharField(max_length=200)` |
| `body` | `TextField()` |
| `created_at` | `DateTimeField(auto_now_add=True)` |

### `migrations/`
Version history of the database schema.
- `__init__.py` — marks it as a package.
- `0001_initial.py` — generated by `makemigrations`; creates the `Post` table when `migrate` runs.

Migration files **are** committed to git so everyone's database matches.

### `admin.py`
Registers models with Django's built-in admin site (`admin.site.register(Post)`), giving a ready-made interface at `/admin/` to add, edit and delete posts.

### `views.py` — the **V** in MTV
Functions that receive a request and return a response.

| View | Returns |
|---|---|
| `index` | Plain text "Hello from the blog app!" |
| `post_list` | All posts rendered with `post_list.html` |
| `post_detail` | One post (or 404) rendered with `post_detail.html` |

### `urls.py` (app)
**Not created by `startapp`** — added manually. Maps paths inside the app to views:

| URL | View | Name |
|---|---|---|
| `/blog/` | `index` | `blog:index` |
| `/blog/posts/` | `post_list` | `blog:post_list` |
| `/blog/posts/<pk>/` | `post_detail` | `blog:post_detail` |

`app_name = 'blog'` namespaces the URL names so templates can use `{% url 'blog:post_list' %}`.

### `templates/blog/` — the **T** in MTV
HTML files with Django template tags. They sit in a sub-folder named after the app to avoid name clashes between apps.
- `post_list.html` — loops over posts with `{% for %}`.
- `post_detail.html` — shows one post.

### `tests.py`
Automated tests run with `python manage.py test blog`. They check that the index page responds and that the list and detail pages show a created post.

## 4. How a request flows

```
Browser:  GET /blog/posts/1/
   │
   ▼
mysite/urls.py      path('blog/', include('blog.urls'))
   │
   ▼
blog/urls.py        path('posts/<int:pk>/', views.post_detail)
   │
   ▼
blog/views.py       post_detail(request, pk=1)
   │        ├── models.py  → Post.objects.get(pk=1)  → db.sqlite3
   │        └── templates/blog/post_detail.html
   ▼
HTTP response (HTML) → Browser
```
